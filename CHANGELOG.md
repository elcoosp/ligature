## v0.1.0-m7 — 2026-11-06

### Features


- *(m7)* Dynamic slot content end to end — fills and fallbacks mount as live fragments (the M6 static-subtree restriction lifted, the first row of its known gaps): scalar binds and events directly on slot content are addressed by slot-scoped run arms (`slot_fill_mut` / `slot_fallback_mut`); fill events attach across slabs at mount time (`attach_foreign` — the handler record lands on the fragment whose reaction set owns the handler); a mounted fallback initializes through a parent-driven init-flush (the parent marks the child's fallback reactions — exact per-reaction mask, event handlers excluded — and flushes the child instance)
- *(m7)* The ref-capture split — `ref={el}` captures the hole NodeId of the fragment the ref lives on, in four phases: direct refs in the build body (byte-stable M0 shape), fill refs through the mounted content, fallback refs through the child's outlet (the parent writes the child's `pub` field), branch refs after the initial flush mounts the branch; every ref field starts as the absent sentinel `NodeId(u32::MAX)`; pinned by a codegen contract test covering all four contexts
- *(m7)* One addressing discipline (`Ctx`) — every run arm (binds, classes, attrs, style props, html, If mounts) resolves its receiver through one classification of the owner fragment: `Direct` / `Branch { slot }` / `Fill { field, slot }` / `Fallback { slot }` (before M7 only Text had a branch special case); the branch-slot lookup becomes the owner dynamic's If/For ordinal instead of the raw children position (M6's fill fragments are tree children too and shifted the index)
- *(m7)* Exact per-member build masks — the initial-flush mask's bit IS the global reaction id; the M0-era `(1 << n) - 1` band marked the wrong component's ids for every component after the first in a module and missed its own late ids (invisible while slot content was static, fatal for the fallback init-flush); script effects still run at build (`effect_multi` pins it), only event-driven handlers are excluded (their bits are exactly the dispatch set)

### Bug Fixes


- *(parse-vue)* Structural directives on slot-content roots were silently stripped — `fragment_from_elem` removed `v-if`/`v-for` before the static-content check ran, so `<template #header><p v-if="on"/></template>` was accepted with the directive erased; now denied with `LIG-E001` before the strip
- *(parse-vue)* Component tags on slot-content roots lowered as plain elements — the use silently vanished from the IR; now denied with `LIG-E001`

## v0.1.0-m6 — 2026-11-06

### Features


- *(m6)* Named slots + `<slot>` fallback end to end (§7.4, ADR-019) — the outlet gains its fallback (`DynamicKind::Slot { name, fallback }`, View IR v5): Vue `<slot name="header">fallback</slot>` and the ligature Solid extension `<Slot name="header">fallback</Slot>` own their fallback fragment; fills match outlets by name (`<template #header>` / `v-slot:header` on the Vue leg, element-valued props `header={<h1>…</h1>}` on the Solid leg, `children={<…/>}` denied); the SFC scanner balances nested `<template>` elements; slot content is a static-subtree contract (dynamic binds inside fills/fallbacks are denied with `LIG-E001` rather than emitted writing nowhere)
- *(m6)* Per-use-site slot mounting — the parent's `build` mounts each use site's fill by name, else the outlet's fallback, else nothing; fill statics ride the parent's prefix and fallback statics the child's (one generated module scope); two latent M0-era defects fixed: the fill lookup matched the first component dynamic of that component anywhere in the module (wrong fill under multi-use), and multi-use parents collided on one child struct field (deterministic `panel_2`-style suffixes now)
- *(m6)* `v-model` sugar (§7.6) — `<input v-model="email" />` lowers to byte-equal IR of the explicit `:value` + `@input` spelling (the `value` Attr dynamic plus the input Event dynamic calling the synthesized setter with `$event.currentTarget.value`); admitted on `<input>` only with a plain state identifier, everything else fail-closed; a unit test pins sugar ≡ explicit
- *(m6)* Multi-statement effect bodies (§7.1) — `createEffect(() => { s1; s2; })` / `watchEffect(() => { … })` lower one post-tier reaction per expression statement (per-statement reads, exact schedules, zero IR change); closes two fail-open holes where block bodies were silently truncated to the first statement and empty bodies lowered to nothing without a diagnostic
- *(m6)* `.map` children take a key (§7.5) — `items().map((item) => <li key={item}>{item}</li>)` strips the attribute and lowers to `ForIr.key` (a plain expression over the item or an arrow taking exactly the item binding; state reads, static keys, duplicates denied); the generated unit runs the M5 `plan_keyed` reconcile unchanged

### Bug Fixes


- *(codegen)* Multi-use component field collision — two uses of one component generated one struct field for both instances; the second and further uses now get deterministic numbered suffixes and the prop-pass run arms address their own instance
- *(sfc)* Nested `<template>` elements closed the enclosing section early — a `<template #header>` fill inside a component truncated the rest of the template into top-level diagnostics; the scanner now balances open/close tags

### Tests


- *(m6)* 23 conformance fixtures (was 19): `slots-named` (two Panel uses — fill on one, fallback on the other), `v-model`, `effect-multi`, `map-keyed`, each with both frontend legs; three new KR-1 demo assertions (per-use-site mounting, the v-model payload write, the two-reaction effect flush); 255 tests across 39 binaries
