## v1.0.0 — 2026-11-08

### Features


- *(m10)* Per-mount component identity end to end (the identity half of M8/M9's first known gap): a component use on an If-branch fragment — content-rooted or direct-rooted, author side or child side — builds as an `Option<Child>` field; the mounting arm rebuilds the instance (`Child::build`) and inserts its root into the branch's component hole through the composed read walk, the unmount arm takes the field and tears the slab down (`inst.frag.teardown(h)` — remount cycles never reuse a stale instance or leak), and the prop-pass arm guards on the instance — the exact mount marking covers the branch subtree's reactions, so a signal written while the branch was absent lands on the NEXT mount (the M8 late-mount discipline generalized to instances)
- *(m10)* The universal attach contract — every component use's root enters its owner's tree at the use hole exactly once per mount: direct uses attach in the build body (`h.insert(s.frag.hole(di), s.<field>.frag.roots()[0], 0)`, before slot assembly), content uses at content mount (M9, unchanged), branch uses per mount — closing the M2-era silent drop where a direct child's DOM never attached (Create commits existed, the positioning insert did not; the commit-stream probe caught it, no test asserted the tree). Zero runtime changes — the primitive is the existing `Host::insert`, and the counter digest is unchanged
- *(m10)* Branch-time slot assembly (the outlet half of the same gap): an outlet on a branch fragment mounts its use-site fill (`SlotOrigin::Fill`) or its own fallback (`SlotOrigin::Fallback`) WITH the branch — the mounting If arm walks the composed accessor chain (`slot_fill_mut` → `branch_mut` → `slot_fill_mut`/`slot_fallback_mut`), mounts the content, and recurses into the freshly mounted content for its outlets and component holes (the M9 walk rooted at a mounted branch); the mount mask widens by the branch-mounted fills' reactions so the fresh content's binds initialize on the next flush pass; `build_content_ctx` grows the branch leg (`map_branch_outlets` — fill contexts compose `Fill { base: Branch { .. } }`) and the unmatched-fill backstop covers the new matches
- *(m10)* Child-side branch outlets mount their own fallbacks — the deep dive's probe: an outlet inside the child's own `<Show>` compiled and rendered an empty hole forever (the M6-era fail-open in a new location); the child's mounting arm now mounts the fallback (child statics, child-local), while FILLS for child-side branch outlets stay codegen-denied (the mount arm is the child's, the fill is parent-authored — cross-component branch-mount coordination is the follow-up mechanism, the backstop keeps them honest)
- *(parse-vue)* Structural directives dispatch on ANY tag — `v-if`/`v-for` check before the component/slot tag dispatch and `fragment_from_elem` dispatches component/slot branch roots (the generalization of M9's `fragment_from_content_root`): `<Badge v-if>`, `<slot v-for>`, and `v-else*` companions lower onto the Solid leg's If/For shapes — closing the fail-open where the directive silently dropped (probe: `<Badge v-if="on">` lowered as an unconditional use)
- *(parse-solid)* The M10 content contract — component uses and nested outlets admit DIRECTLY inside BRANCH bodies of slot content (per-mount identity + branch-time assembly); LIST bodies deny with one precise reason each (per-item instance identity is the keyed-component story)
- *(parse-solid)* The own-tree contract — component uses and outlets inside FOR bodies of the component's own template deny with one precise reason each; the deep dive's probes showed both lowered silently broken (a never-mounted outlet hole per item; one eager component field shared by every item, its root detached). If branches admit (per-mount identity)
- *(perf)* The `codegen/branch` bench workload (module codegen over the slots-branch-component fixture — the rebuild/dispose arms, the assembly walk, the widened masks) with the `codegen_branch` ledger row: release median 1 065 µs against a 6 000 µs ceiling (≈5.6× headroom); the ledger enforces 12 rows in release
- *(lints)* The tree carries ZERO `#[allow]`/`#![allow]` attributes: the workspace table carries pedantic (warn + CI `-D warnings`), every suppression lives in `[lints]` tables with a rationale comment, `lig-patch`'s unsafe surface and the generated-code hygiene live in per-crate tables or `#![expect]` with reasons, and the generator emits plain code — the generated lint blanket moved to the compile-clean crate's `[lints]` (the counter digest is unchanged; the unit grew 7 437 → 7 385 B through the blanket move and the M10 build-phase doc)

### Bug Fixes


- *(codegen)* A direct component use's root never entered the parent's tree — every nested component tree rendered detached since M2 (the demo tests asserted props and slot state, never the tree); the build body now attaches each direct use at its use hole before slot assembly
- *(codegen)* A component use on a branch fragment reused the eager M0 field — one instance, its root never inserted, its prop-pass writing into it regardless of mount state; per-mount identity rebuilds and disposes with the branch
- *(codegen)* An outlet inside a branch fragment (child's own tree) rendered an empty hole forever — nothing mounted its fallback; the branch-time assembly mounts it with the branch
- *(parse-vue)* `v-if`/`v-for` on component and slot tags silently dropped — the tag dispatch ran before the directive check; the reorder + the branch-root dispatch lower the chain shapes verbatim

### Tests


- *(m10)* 27 conformance fixtures → 29: `slots-branch-component` (per-mount identity: build → dispose → late write → remount, both legs) and `slots-branch-outlet` (branch-time fill and fallback mounts + composed-walk updates, both legs); the KR-1 demo pins the rebuild/dispose cycle, the branch-time mounts, and the unmount taking its content with it; 287 tests across 39 binaries


### Features


- *(m9)* Component-in-content end to end — grandchild prop-pass THROUGH mounted instances (the Component half of M8's first known gap): a component use inside slot content builds as the content author's struct field (the use walk already reaches content fragments — they are tree children); the parent's slot assembly inserts the grandchild's DOM root into the mounted content's component hole at mount time (`h.insert(content.hole(n), s.<field>.frag.roots()[0], 0)` — the existing `Host::insert` primitive, zero runtime changes), and the prop-pass run arm (ctx-independent, the author's bind reaction) writes the grandchild's setters and flushes the instance — the exact build mask covers initialization and the initial flush runs after slot assembly, so props land on a mounted grandchild; the prop-pass arm clones non-literal prop values (a state-read `String` prop moved out of `self` while the child-field borrow was live — caught by the new fixture at compile-clean)
- *(m9)* Composed fill contexts — `Ctx::Fill` grows a base field and an accessor selector (`Fill { field, slot, fill, base }`: `fill` selects `slot_fill_mut` vs `slot_fallback_mut` for fills matched to outlets inside the child's fallback content) and `Ctx::Fallback` grows the same base for the child's own nested fallbacks; `ctx_scope`/`ctx_frag_read` compose base-first and `base = Direct` reproduces the M7 emission byte-for-byte (every existing gen artifact regenerated byte-identical, counter digest unchanged); `build_content_ctx` becomes a two-sided walk — child side (root outlets + the child's own fallback contents) and author side (nested outlets inside the use site's own fill contents)
- *(m9)* Nested outlets end to end — a `<Slot name="inner">` on slot content mounts its use-site fill or its own fallback at content-mount time through the composed accessor chain, then the walk recurses into the freshly mounted content for ITS outlets and component holes; binds on nested fill content walk the composed chain (`slot_fill_mut` → `slot_fill_mut`), binds on nested fallback content the fallback accessor (`slot_fill_mut` → `slot_fallback_mut`), nested fallback content joins the fallback init-flush subtree, and the origin gates hold (a filled outlet's fallback accessor sees nothing — a fallback write can never cross into a fill)
- *(parse-solid)* The M9 content contract — component uses and nested outlets admit DIRECTLY on fill/fallback content; the walk carries the structural position (`in_branch`/`in_list_item`), and component uses/outlets inside branch or list bodies of content stay denied with one precise reason each (a remounted branch would re-insert a root the previous teardown destroyed — per-mount instance identity is the follow-up, per-item instances the M2 keyed-component story)
- *(parse-vue)* Content-root dispatch for slot/component tags — root `<slot>` tags and root component tags lower ONTO the content fragment (`fragment_from_content_root` dispatches them; the M8 denials existed because `lower_element` does not dispatch the tag), chain-tail roots stay denied, and a structural directive on a slot/component content root denies with `LIG-E001` (the dispatch lowers the outlet/use itself, not a wrapper — closing the silent-drop shape)

### Bug Fixes


- *(codegen)* A use-site fill naming no outlet the use can reach silently never mounted — the M6-era fail-open shape; now a fail-closed codegen error (the fill-matching walk covers the child's root, its fallback contents, and the use site's own fill contents, so anything unmatched is a real mistake)
- *(codegen)* Prop-pass arms moved `String` state out of `self` — non-literal prop values now clone (setters take their value by value)

### Tests


- *(m9)* 25 conformance fixtures → 27: `slots-component` (grandchild prop-pass through the mounted fill, both legs) and `slots-nested` (nested outlet filled on one use site, own-fallback on the other; both legs); the KR-1 demo pins the grandchild insert + prop flow, the nested fill/fallback mounts, the composed-walk updates, and the origin gates; 276 tests across 39 binaries

## v0.1.0-m8 — 2026-11-06

### Features


- *(m8)* Structural slot content end to end — the M7 If/For-in-content denial lifted (the If/For half of its first known gap): fills and fallbacks are full program surfaces (binds, events, refs, AND If/For at any depth); an If inside slot content mounts its branch ON the mounted content through the composed walk (`slot_fill_mut`/`slot_fallback_mut` → the content receiver → `mount_branch`), and the mount marks the fresh branch subtree's non-handler reactions so its binds initialize on EVERY mount (the flush re-enters through the union — a remount picks up writes made while the branch was absent); branch events attach across slabs at mount (`attach_foreign`), branch refs capture per mount through the read walk
- *(m8)* Composed `Ctx` contexts — `Branch { slot, base: Box<Ctx> }` composes over the parent fragment's context; `ctx_of` recurses (branch wrapper → content map → `Direct`), `ctx_scope` unwraps outermost-first with shadowing receivers, and the read walk (`ctx_frag_read`) yields `Option<&Fragment>` for mount-time reads; the composition closes two M7-era latent holes the flat enum could not express: nested Ifs (an inner-branch bind addressed `self.frag.branch_mut` and skipped the outer level) and For-in-branch (the reconcile method hard-addressed `self.frag`) — both pinned by codegen contract tests
- *(m8)* The composed For reconcile — Direct-rooted lists keep the M0 `&mut self` method shape (byte-stable); composed lists emit a receiver-param associated fn (`Self::reconcile_fN(h, recv, slot, items, reads…)`) — the run arm pre-clones source + reads, unwraps the composed walk, and calls the associated fn (no `self` borrow overlap); `plan_keyed` and the per-item bind replay run verbatim on the content's own list table
- *(m8)* Subtree-wide fallback init-flush — with structural fallbacks, the content's branch/list fragments own reactions too; the parent's exact per-reaction mask covers the whole fallback subtree (event handlers excluded by id), so the fallback's If arms mount the content's own branches and its branch binds initialize inside the parent-driven flush
- *(parse-vue)* Content-root structural directives — `v-if`/`v-for` on slot-content roots lower ONTO the content fragment (`fragment_from_content_root`; the M7 denial existed because the strip silently dropped the directive — the M6-era fail-open shape); `v-else-if`/`v-else` roots (no chain to join), root component tags, and root `<slot>` tags stay denied — the last closing a second fail-open (`lower_element` does not dispatch the tag, so a nested outlet silently lowered as a plain element)
- *(parse-solid)* The M8 content contract — If/For inside fills/fallbacks admitted at any depth (the contract walk recurses through branch/body fragments); component uses, nested outlets, and children/prop-pass/whole-style stay fail-closed with one reason each; events inside content For bodies stay denied (the LIG-E118 discipline)

### Tests


- *(m8)* 24 conformance fixtures → 25: `slots-structural` (a fill carrying an If with a disjoint-read bind — the mount-marking pin — and a keyed For; the unfilled outlet mounts the child's structural fallback), each with both frontend legs; the KR-1 demo pins late-mount re-initialization, the keyed reconcile inside the content, and the subtree-wide fallback init-flush; 268 tests across 39 binaries

## v0.1.0-m7 — 2026-11-06

### Features


- *(m7)* Dynamic slot content end to end — fills and fallbacks mount as live fragments (the M6 static-subtree restriction lifted, the first row of its known gaps): scalar binds and events directly on slot content are addressed by slot-scoped run arms (`slot_fill_mut` / `slot_fallback_mut`); fill events attach across slabs at mount time (`attach_foreign` — the handler record lands on the fragment whose reaction set owns the handler); a mounted fallback initializes through a parent-driven init-flush (the parent marks the child's fallback reactions — exact per-reaction mask, event handlers excluded — and flushes the child instance)
- *(m7)* The ref-capture split — `ref={el}` captures the hole NodeId of the fragment the ref lives on, in four phases: direct refs in the build body (byte-stable M0 shape), fill refs through the mounted content, fallback refs through the child's outlet (the parent writes the child's `pub` field), branch refs after the initial flush mounts the branch; every ref field starts as the absent sentinel `NodeId(u32::MAX)`; pinned by a codegen contract test covering all four contexts
- *(m7)* One addressing discipline (`Ctx`) — every run arm (binds, classes, attrs, style props, html, If mounts) resolves its receiver through one classification of the owner fragment: `Direct` / `Branch { slot }` / `Fill { field, slot }` / `Fallback { slot }` (before M7 only Text had a branch special case); the branch-slot lookup becomes the owner dynamic's If/For ordinal instead of the raw children position (M6's fill fragments are tree children too and shifted the index)
- *(m7)* Exact per-member build masks — the initial-flush mask's bit IS the global reaction id; the M0-era `(1 << n) - 1` band marked the wrong component's ids for every component after the first in a module and missed its own late ids (invisible while slot content was static, fatal for the fallback init-flush); script effects still run at build (`effect_multi` pins it), only event-driven handlers are excluded (their bits are exactly the dispatch set)

### Bug Fixes


- *(parse-vue)* Structural directives on slot-content roots were silently stripped — `fragment_from_elem` removed `v-if`/`v-for` before the static-content check ran, so `<template #header><p v-if="on"/></template>` was accepted with the directive erased; now denied with `LIG-E001` before the strip
- *(parse-vue)* Component tags on slot-content roots lowered as plain elements — the use silently vanished from the IR; now denied with `LIG-E001`
