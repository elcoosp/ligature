## v0.1.0-m3 — 2026-11-06

### Features


- *(m3)* Incremental pipeline, digest gating, watch mode, ThinLink patch engine — the salsa-style session engine `lig-incremental` (digest-gated memos, revision counters, cycle recovery) behind `lig check/build/watch`, digest-gated re-emission with `dist/build-state.json` (D-9 gate `lig incremental`), `lig watch` with `--once`, LIG-E020 component-cycle Deny via the §11.1 build order, per-arm source-map attribution, the embedded error catalog + `lig doctor`, and the two-generation patch spike with stub thunks and the never-dlclose proof (48d2c01)
- *(m3)* Per-bit dispatch spill refinement — `Schedule.writes_hi` carries per-reaction spill masks (ids 64..128, bits are id − 64), setters/memos/build emit exact per-bit init masks, `flush` dispatches spill reactions per bit; reaction cap 64 → 128, fail-closed past it
- *(m3)* ThinLink engine in `lig-patch`: `PatchSession` chains generations with per-symbol classification (`Existing`/`StubThunk`/`New`), `captured_address`/`call_captured` prove stale-generation code stays executable (ADR-016)

### Breaking Changes


- `lig_runtime::Schedule` gains the `writes_hi` field: generated schedule literals (and hand-written hosts) must add `writes_hi: &[]` for components within the 64-reaction fast path — regenerated fixtures, snapshots, and the runtime bench pin the field
