# M9 milestone report — component-in-content (grandchild prop-pass) and nested outlets (composed fill contexts)

Date: 2026-11-08 · Toolchain: 1.99.1 (MSRV 1.97, ADR-012) · Runner: Linux x86_64

## Scope delivered (the Component/Slot half of M8's first known gap)

M8's report deferred "Component uses inside slot content and nested outlets
inside slot content": component-in-content needs grandchild prop-pass
THROUGH mounted instances, nested outlets need composed fill contexts (a
`Fill` base field and per-instance addressing). M9 lifts both — fills and
fallbacks now compose the full component surface — through the composed
contexts ADR-021 reserved the base field for, per-instance field
addressing the use-site machinery already had, and one new mount-time
commit that rides the EXISTING `Host::insert`. No new crates, no new error
codes, no new external dependencies, no IR change (schema stays v5), **zero
runtime changes** — the grandchild's DOM root entering the mounted content
is the same commit-stream primitive `mount_slot` already uses.

## Notes and decisions

- **Why zero runtime changes**: the grandchild's root entering the
  mounted content is a `Host::insert` commit — the commit stream is the
  only tree-mutation surface, and `mount_slot` already inserts through
  it. The runtime's origin-gated accessors (`slot_fill_mut` /
  `slot_fallback_mut`) do the M9 safety work for free: a nested fill and
  a nested fallback address DIFFERENT accessors, so a fallback write
  into a fill (or vice versa) stays unrepresentable.
- **Why the grandchild keeps the Direct ownership shape**: the instance
  is a struct field of the content author (the use walk already reaches
  content fragments — they are tree children), so the prop-pass arm is
  the author's ctx-independent bind reaction and the schedule/mask
  machinery applies unchanged. The mounted content only adds the
  MOUNT-TIME story: insert at mount, props land on the next flush —
  which is the build's initial flush, running after slot assembly.
- **Why components inside branch/list bodies of content stay denied**: a
  remounted branch would re-insert a root the previous teardown already
  destroyed (the instance is per-mount, not per-component). Honest
  lifting needs per-mount instance identity — rebuild per mount — which
  is a different mechanism than re-addressing an existing field. The
  same reasoning denies outlets there (they mount with their branch) and
  keeps per-item components the M2 keyed-component story.
- **Why `Fill` carries an accessor selector instead of a second
  variant**: a fill matched to an outlet inside the child's FALLBACK
  content addresses it through `slot_fallback_mut` on the child
  instance — the child-side `Ctx::Fallback` shape cannot express that
  (it addresses `self.frag`, the generating component's own fragment).
  One variant with a `fill: bool` selector keeps `ctx_scope`
  byte-stable for `base = Direct` and composes otherwise.
- **Why the fill-matching walk covers the child's fallback contents**:
  an outlet inside a child-authored fallback is only live when the
  fallback mounts — a fill for it mounts exactly then (the walk mounts
  it while mounting the fallback), never silently. When the use site
  fills the outlet the fallback hangs on, the fallback — and the nested
  fill with it — never mounts: deterministic, not dropped.
- **Why the unmatched-fill backstop is a codegen error, not a lint**: a
  fill that names no reachable outlet produced zero mounts and zero
  diagnostics — the worst kind of silent drop (BR-1's spirit applied to
  emission). Fail-closed beats a lint the author can ignore.

## Known gaps (deferred, deliberate)

- Components and outlets inside branch/list bodies of slot content:
  fail-closed (`LIG-E001`, per-mount/per-item instance identity — rebuild
  per mount; the M2 keyed-component story).
- Outlets inside the child's own BRANCH fragments (`<Show when={…}>
  <slot/></Show>` in the child): the child-side fill-matching walk does
  not descend branches — a fill for such an outlet is now a codegen
  error (the backstop), not a silent drop. Branch-mount-time fill
  coordination is the follow-up.
- Direct-rooted branch binds initialize via co-read marking only (the
  M0 shape is unchanged); the `else_`/`v-else` mount arm still mounts
  the `then` branch only — both pre-existing, deferred.
- `v-model` on non-input elements (checkbox/radio/select) and
  `<slot :name>` forwarding: fail-closed today (M6 gap, unchanged).
- Template refs on the Vue leg: the Solid leg's `ref={local}` works end
  to end; the Vue template has no `ref` spelling yet — a two-leg ref
  fixture waits for that lowering.
- `cargo vet` (§14.2 supply-chain onboarding, ADR-012): still deferred —
  the pin table remains the reviewed surface.
- A `lig patch` developer driver over real app dylibs (app-crate scaffold
  + dev channel): the engine surface is what that work wires into.
