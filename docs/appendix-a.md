# Appendix A — the annotated generated unit

Every gate in this repository pins one artifact in some way; exactly one
artifact is pinned by all of them at once: the generated Rust for the
`counter` fixture, committed at `fixtures/generated/counter.rs` and
byte-pinned by `lig reproducibility` (D-8 — **7 146 bytes**,
`0x85d06a5c087b3589` component digest). This appendix walks that file top
to bottom: what each shape is, which architecture section it implements,
and which gate holds it still. Read it next to the file — the quotes here
are its actual bytes except where `/* … */` marks a true elision, so the
document cannot drift silently: a codegen change fails `lig
reproducibility` first, and the appendix diff is reviewed in the same
change.

The source it is generated from is `fixtures/conformance/counter/input.solid.tsx`
(a signal, a memo, a delegated click, a `Show`-shaped conditional, static
class, style consts) — deliberately the smallest program that exercises
every compiler stage.

```text
unit:  counter.rs
size:  7 146 B (budget: 8 192 B — `lig budgets`, row gen_counter_bytes)
maps:  dist/maps/counter.map.json — chained VLQ, per-arm attribution (M3)
ir:    dist/ir/counter.json — canonical View IR v2 (§5.6)
```

## 1. Header and hygiene

```rust
/**generated by ligature — do not edit
source: counter.tsx (component digest 0x85d06a5c087b3589)*/
#[allow(
    clippy::all,
    clippy::pedantic,
    missing_docs,
    non_upper_case_globals,
    unused_parens,
    unused_variables,
    dead_code
)]
pub mod generated {
    use ::lig_runtime::prelude::*;
```

The header names the source and its content digest: the unit is
reproducible, and the digest is what D-9's digest-gated re-emission compares
against `dist/build-state.json` before deciding to write anything. The
module is fully qualified (`::lig_runtime`) so the unit cannot be shadowed
by app-local names, and the hygiene `#[allow]`s are scoped to the generated
module only — the app's lints are untouched. Everything below lives in that
module; the tail re-exports the component:

```rust
pub use generated::Counter;
```

## 2. The component struct is the state slots (§7)

```rust
    pub struct Counter {
        pub count: i64,
        pub doubled: i64,
        pub ev: ::lig_runtime::EvData,
        pub frag: ::lig_runtime::Fragment,
    }
    #[derive(Default)]
    pub struct CounterProps {}
```

One plain struct per component: a field per state slot (`count` the signal,
`doubled` the memo — types from the small-lattice typer), the event-payload
slot the delegated handler reads, and the `Fragment` — the runtime's node
slab + anchor + dirty-bit handle (§10). No interior mutability, no cells:
writes are monomorphic method calls on `&mut self`, which is what makes the
whole component a single `&mut` owner the scheduler can reason about.
`CounterProps` is the (empty) external contract — `destructure-props`
fixtures show the populated form.

## 3. Templates are consts (§9.2, template inlining)

```rust
    pub static Counter_TPL_T0: &[::lig_runtime::TplNode] = &[
        ::lig_runtime::TplNode::Element {
            tag: "div",
            attrs: &[
                ::lig_runtime::TplAttr {
                    key: "class",
                    val: ::lig_runtime::AttrVal::Str("counter p-4"),
                },
            ],
            style: Some(::lig_runtime::StyleConstId(0u32)),
            children: &[ /* button(Add), span(Marker), Marker */ ],
        },
    ];
```

The static shape of the view compiles to a `static` tree of
`TplNode`/`TplAttr` values the runtime instantiates in one walk (`static-template`
fixtures reduce to exactly this with zero dynamics). Dynamic holes are
`Marker` nodes; the branch template `T1` (`<p class="hot">`) is a second
const, mounted/unmounted by the conditional reaction below. `StyleConstId(0)`
indexes into the style table (§8/D-12):

```rust
    pub static Counter_STYLE_CSS: &[&str] = &["display:flex;padding:16px"];
```

The `taffy` profile's const-fn emitter produced that string from the
author's style object; `lig-style`'s 25-property schema is what bounds it.

## 4. Anchors: how holes find their nodes (§5)

```rust
    static Counter_HOLE_ANCHORS_F0: &[&[::lig_runtime::AnchorStep]] = &[
        &[::lig_runtime::AnchorStep::Down(0u32)],
        &[::lig_runtime::AnchorStep::Down(1u32), ::lig_runtime::AnchorStep::Down(0u32)],
        &[::lig_runtime::AnchorStep::Down(2u32)],
    ];
    static Counter_BRANCH_ANCHORS_F0: &[&[::lig_runtime::AnchorStep]] = &[
        &[::lig_runtime::AnchorStep::Down(2u32)],
    ];
```

Each dynamic resolves its target node by walking the instantiated tree with
`AnchorStep`s — `Down(n)` into the *n*-th element child, `MarkerDown(0)`
into the first marker. The paths are assigned by `lig-ir::anchor` (the
frontend-agnostic walk ADR-014 moved out of the Solid frontend). Hole 1's
two-step path (`Down(1)`, `Down(0)`) is the `<span>`'s text marker; the
branch anchor points at the third child, where `T1` mounts.

## 5. The schedule literal (§7.2 — the M3 refinement)

```rust
    static Counter_SCHEDULE: ::lig_runtime::Schedule = ::lig_runtime::Schedule {
        order: &[0u8, 1u8, 2u8, 3u8, 4u8],
        writes: &[24u64, 5u64, 0u64, 0u64, 0u64],
        writes_hi: &[0u64, 0u64, 0u64, 0u64, 0u64],
    };
    const Counter_READS_COUNT: u64 = 5u64;
    const Counter_READS_DOUBLED: u64 = 24u64;
```

This is the const topological schedule, the heart of the architecture's
reactivity story. `order` is the reaction execution order (`lig-reactivity`'s
toposort over reader/writer masks, build-order-cycled by LIG-E020 when
components import each other). `writes[r]` is the re-dirty mask each
reaction hands back to the flush loop: reaction 0 (the memo) writes
`24 = 0b11000` — reactions 3 and 4, the two bindings that read `doubled`;
reaction 1 (the effect that calls `set_count`) writes `5 = 0b101` — the memo
and the text binding that read `count`. `writes_hi` is the M3 spill word for
reactions 64..128 (per-bit dispatch refinement); this component sits in the
fast path, so the row is exact zeros rather than absent — the M3 report's
"+52 B for the `writes_hi` row". The `READS_*` constants are the reader
masks each state feeds the schedule with (`READS_COUNT = 0b101`: reactions
0 and 2 read `count`; `READS_DOUBLED = 0b11000`: reactions 3 and 4 read
`doubled`) — they are the named inputs the `writes` cascade was derived
from (`WRITES[r]` = OR of the reader masks over the fields `r` writes),
emitted into the unit so the schedule is auditable without re-deriving it.

## 6. Reaction ids and the write path (§9.2, §10.1)

```rust
    const Counter_R0_MEMO_DOUBLED: u8 = 0u8;
    const Counter_R1_FX: u8 = 1u8;
    const Counter_R2_BIND_D1: u8 = 2u8;
    const Counter_R3_BIND_D2: u8 = 3u8;
    const Counter_R4_BIND_D0: u8 = 4u8;
```

Named constants for every reaction — the names appear in `names[]` of the
emitted source map, which is what makes `lig resolve` answer with the *IR
node* a generated line came from (§9.4; per-arm attribution since M3 means
each reaction's body region maps back to its own expression).

The only write path for a signal is the generated setter — one store plus
the dirty mark:

```rust
        pub fn set_count(&mut self, v: i64) {
            self.count = v;
            self.frag.mark_mask(5u64);
        }
```

and the dispatch glue for the delegated click (§10.1 — events are data,
no closures were allocated anywhere: the host's delegate table routes DOM
events to `fire_1`):

```rust
        pub fn fire_1(&mut self, h: &mut dyn Host, ev: &::lig_runtime::EvData) {
            self.ev = ev.clone();
            self.frag.dirty.set(1usize as usize);
            ::lig_runtime::flush(self, h);
        }
```

capture the payload, mark the handler reaction, flush.

## 7. Run-once build (C4)

```rust
        pub fn build(h: &mut dyn Host, props: CounterProps) -> Self {
            let mut s = Self {
                count: 0i64,
                doubled: 0,
                ev: ::lig_runtime::EvData::new(),
                frag: ::lig_runtime::Fragment::new(
                    h,
                    Counter_TPL_T0,
                    Counter_HOLE_ANCHORS_F0,
                    Counter_BRANCH_ANCHORS_F0,
                ),
            };
            s.frag
                .attach(
                    h,
                    0usize,
                    ::lig_runtime::EventKind::Click,
                    ::lig_runtime::HandlerId(1u32),
                    true,
                );
            s.frag.mark_mask(0x1d);
            ::lig_runtime::flush(&mut s, h);
            s
        }
```

`build` executes top to bottom and never branches: instantiate the root
template, attach the delegated handler, mark every initial reaction
(`0x1d = 0b11101` — the memo and all three bindings; the click effect is
event-dispatched, so build does not mark it. Exact per-bit masks are the
M3 init refinement, no more mark-everything `u64::MAX`), and run the first
flush. Reactivity lives exclusively in reactions; `build` is ordinary
straight-line Rust, which is what makes the KR-1 compile-clean gate
meaningful — generated code either compiles against the mock host or the
workspace does not build.

## 8. The `Reactions` impl: one match, the patchable site (§9.2, §11.4)

```rust
    impl ::lig_runtime::Reactions for Counter {
        fn schedule(&self) -> &'static ::lig_runtime::Schedule { &Counter_SCHEDULE }
        fn dirty(&mut self) -> &mut ::lig_runtime::DirtySet { &mut self.frag.dirty }
        fn run(&mut self, h: &mut dyn Host, r: u8) {
            match r {
                Counter_R0_MEMO_DOUBLED => {
                    let next = (self.count * 2i64);
                    if next != self.doubled {
                        self.doubled = next;
                        self.frag.mark_mask(24u64);
                    }
                }
                Counter_R1_FX => { self.set_count((self.count + 1i64)); }
                Counter_R2_BIND_D1 => {
                    let mut buf = [0u8; 20];
                    self.frag.set_text(h, 1usize, ::lig_runtime::format_i64(&mut buf, self.count));
                }
                Counter_R3_BIND_D2 => {
                    let on = (self.doubled > 10i64);
                    if self.frag.branch_is(0usize) != on {
                        if on {
                            self.frag
                                .mount_branch(h, 0usize, Counter_TPL_T1, /* anchors */);
                        } else {
                            self.frag.unmount_branch(h, 0usize);
                        }
                    }
                }
                Counter_R4_BIND_D0 => { /* the branch's text hole ← doubled */ }
                _ => {}
            }
        }
    }
```

Three things to notice. First, `run` is monomorphic dispatch on a `u8` —
the safepoint-shaped site §11.4 patches (a ThinLink generation replaces
bodies, the jump table routes `run`). Second, the memo guards its own write
(`if next != self.doubled`) — equality suppression is generated per memo,
so the flush loop's write-mask cascade stays exact. Third, the text binding
formats into a **stack buffer** (`[0u8; 20]`) via `lig_runtime::format_i64`
— the §14.3 alloc-free formatting rule: no `String`, no `format!`, nothing
that allocates on the hot path (the runtime crate cannot reach std even if
it wanted — see the next section).

## 9. The runtime contract this unit stands on (§10, M4)

Everything above links exactly one crate: `lig-runtime` — `#![no_std]`,
`#![forbid(unsafe_code)]`, **zero dependencies**, `std` only under
`#[cfg(test)]`. M4 turns that description into a proof: `lig no-std`
compiles the crate for `thumbv7em-none-eabihf` and
`aarch64-unknown-none-softfloat` (no std, no host allocator), then compiles
a fresh copy of *this unit* inside a `#![no_std]` scratch crate against it.
The generated code is host-agnostic for the same reason the runtime is: it
never names std, only `core`/`alloc` types that come from the prelude —
which is also why the unit needs no `extern crate std` and no allocator
wiring to link on a bare-metal host.

## 10. The budget row (§14.2, M4)

The unit is a budget line item, too: `lig budgets` measures its size
(`gen_counter_bytes` — 7 146 B against an 8 192 B ceiling, enforced in
every profile) and every stage that produced it (lower, canonical IR,
codegen — `docs/benchmarks/budgets.toml` holds the full ledger with the
reference medians). A regression in any of them fails CI with the row, the
measured number, and the provenance note; raising a ceiling is a reviewed
contract change like this document.

## Regenerating

```sh
lig fixtures gen        # rewrites fixtures/generated/counter.rs (+ the gen crate)
lig reproducibility     # byte-diffs the committed unit against a fresh generation
lig budgets             # re-measures the ledger rows (release: enforces)
lig no-std              # re-proves the §10 contract over a fresh unit
```

The unit is a golden file: regenerate only to review a deliberate contract
change, and expect this appendix, the reproducibility gate, and the budget
ledger to move together.
